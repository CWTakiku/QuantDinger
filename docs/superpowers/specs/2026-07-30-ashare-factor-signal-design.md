# A 股技术因子研究 + 周频信号邮件设计

日期：2026-07-30  
状态：已审阅通过（2026-07-30）；补充 Tushare 为 A 股主数据源  
范围：第一阶段（技术因子 + Tushare）；第二阶段（基本面）仅划边界、不实现

## 1. 目标与非目标

### 目标

- 在 QuantDinger 上基于 A 股（`CNStock`）做技术因子研究与策略验证。
- **A 股日线/成分优先使用运营商 Tushare API**（自定义 HTTP 基址 + Token，仅环境变量，禁止入库/提交）。
- 股票池同时覆盖 `csi300`（沪深300）与 `csi500`（中证500），结果可对比。
- 策略以**周频调仓**产生交易意图，通过 **`executionMode=signal`** 部署，**邮件**推送，不下单。
- 研究链路：因子 IC / 分位筛选 → Strategy API V2 固化 → 回测 → signal + 邮件。

### 非目标（第一阶段明确不做）

- A 股券商 / QMT 等实盘对接。
- 基本面多因子实装（仅预留第二阶段数据与接口边界）。
- 完整官方历史成分调入调出重建。
- 做空、日内交易、日频刷邮件。

## 2. 约束（已确认）

| 项 | 选择 |
|---|---|
| 实盘 | 不需要；信号推送即可 |
| 研究重心 | 技术因子先行；基本面后续 |
| 股票池 | `csi300` + `csi500` 都跑 |
| 通知渠道 | 邮件（SMTP） |
| 调仓节奏 | 周频（由日频改为周频） |
| 实现路径 | 方案 2：Strategy API V2 + signal + 邮件 |
| A 股数据源 | Tushare（gyzcloud 代理 HTTP）为主；现有腾讯/yfinance/AkShare 作 fallback |

### 数据源环境变量（禁止提交真实值）

| 变量 | 含义 |
|---|---|
| `TUSHARE_TOKEN` | Tushare Token |
| `TUSHARE_HTTP_URL` | API 基址，例如运营商提供的 `https://…/api` |

## 3. 架构

```text
Tushare（日线 / 指数成分）→ CNStock 数据源
        ↓
因子筛选（IC / Rank IC / 分位收益，csi300 & csi500）
        ↓
策略源码（技术因子选 Top-N，仅做多，周调仓）
        ↓
回测验证（成本/滑点、双池对比）
        ↓
部署 executionMode=signal（不下单）
        ↓
邮件通知（开仓 / 调仓 / 平仓意图）
```

### 组件职责

| 组件 | 职责 | 依赖 |
|---|---|---|
| Tushare 客户端 | Token + 自定义 HTTP；日线、可选成分 | `TUSHARE_TOKEN` / `TUSHARE_HTTP_URL` |
| `CNStockDataSource` | A 股 K 线：Tushare 优先，再 fallback | `cn_stock.py` + 现有 asia 链路 |
| 因子研究（现有 API + registry） | 技术因子计算、截面 IC/分位诊断 | `CNStock` K 线、公开股票池 |
| 示例策略（Strategy API V2） | 周调仓、Top-N 等权、long_only | `pool=csi300|csi500`、`momentum` period=20 |
| 回测运行时 | 与信号共享同一源码契约 | Strategy V2 回测 |
| Signal 部署 | 调度策略、产生规范信号动作 | `executionMode=signal` |
| 通知层 | SMTP 发信、去重、失败日志 | `SMTP_*` + `notification_config` |

### 边界

- 第一阶段只用内置**技术因子** + 股票池（优先 Tushare 成分/行情，池元数据仍可走平台 `csi300`/`csi500`）。
- 不接 A 股券商；signal 只发邮件。
- 基本面多因子单独第二阶段。
- **真实 Token 不得写入仓库、设计稿正文或日志。**

## 4. 因子集合与选股规则

### 研究侧

- 池子：`csi300`、`csi500` **分开**计算与对比，不混池。
- 起步因子（少而可解释）：
  - 动量：`momentum` / `roc`（默认约 20 日窗，参数可配）
  - 反转：短窗收益或 RSI 类
  - 波动：`realized_volatility` 或 ATR —— 主要作风控过滤，不当唯一主收益因子
- 前瞻收益：与周调仓对齐，使用**周收益**评估 IC / 分位。
- 通过标准（可调经验门槛）：覆盖率足够、Rank IC 方向相对稳定、分位收益大致单调。

### 策略侧

- 方向：仅做多（`long_only`）。
- 调仓：每周一次；用最新有效因子截面排序，持有 **Top-N**（默认 N=10，策略参数可配）。
- 权重：等权（或近等权）；仓位变化集中在调仓日。
- 过滤（按平台可得字段实现）：停牌/无有效行情、波动过高可剔除。
- 部署形态：示例策略默认 `pool=csi300`（`initialize` 内写死）；`csi500` 需复制策略并在 `initialize` 中改 `context.set_universe(pool=...)` 与 `context.set_benchmark(...)`（见 §9 交付物）。Strategy V2 禁止在 `initialize` 内读取 `context.params`，故不能通过运行时参数切换股票池。
- **第一版示例策略默认主因子**：20 日动量（`momentum`/`roc`，参数可改）。研究阶段可对比反转等因子，但交付示例不阻塞在「必须先跑完全量 IC」上；用户验证后可改参数或换因子 ID。

### 刻意不做（第一阶段）

- 做空、日内、基本面因子写入选股、实盘下单。

## 5. 回测、信号与邮件

### 回测

- 用日线行情计算因子；**每周调仓一次**。
- 调仓日语义：优先对齐平台已有调度能力；建议「周频 rebalance 回调」或等价的周结束/周初语义，并在策略 docstring 与参数中写死约定，避免回测与 signal 不一致。
- 成本：手续费、滑点可配；A 股数量按整手约束（普通标的 100 股/手、科创板开仓最低 200 股）；涨跌停等撮合细节第一版仍简化，以信号意图与组合表现为主。
- 输出：净值、回撤、换手、持仓快照；双池分别报告。
- 通过门槛：无未来函数；周调仓行为符合预期；邮件字段可从信号意图审计还原。

### Signal 部署

- `executionMode=signal`：产生开仓/调仓/平仓意图，**不向交易所/券商下单**。
- 与回测共用同一策略源码。
- 非调仓日：默认静默（或仅异常告警），避免按日刷邮件。

### 邮件

- 渠道：平台 SMTP（`NOTIFICATION_EMAIL` 相关配置）。
- 正文建议字段：策略名、股票池、调仓日、动作、标的、目标权重、所用因子名、简要理由。
- 同一调仓周期去重：持仓意图未变则不重复发送。
- 发送失败：记日志并可按平台通知层重试；**不回滚**已生成的信号意图；策略循环不因邮件失败中断。

## 6. 错误处理

| 情况 | 行为 |
|---|---|
| 单票行情/因子失败 | 跳过该票，继续整池；日志含 symbol 与原因 |
| 池为空或覆盖率过低 | 本周不调仓；告警邮件或仅日志（参数可配） |
| 邮件失败 | 错误日志 + 通知层重试；不中断策略、不撤销信号意图 |
| 因子计算异常 | 该因子本周禁用并告警，禁止静默使用错误值 |

## 7. 测试与验收

### 自动化（实现时）

- 单元：截面排序、Top-N、周调仓日判定、邮件正文组装（SMTP mock）。
- 契约：策略通过 Strategy V2 校验（`initialize`、universe、long_only、周调度）。

### 手工验收

- 短区间回测可肉眼看到每周持仓变化。
- signal 部署能收到至少一封样例调仓邮件。
- `csi300` 与 `csi500` 可分别跑通并对比。

## 8. 第二阶段边界（不进入第一版实现）

- 基本面多因子：依赖 `qd_fundamental_snapshots` 的 PIT 数据；CN 侧需自备导入或后续补同步能力后再扩策略。
- 仍不默认接 QMT/实盘；通知仍以邮件为主（可再加渠道）。
- 成分股完整官方历史：有可靠数据源后再升级；第一版接受公开快照偏差，并在操作说明中注明存活偏差风险。

## 9. 交付物（第一阶段实现时）

1. 可运行的示例策略（参数可切 `csi300` / `csi500`，周调仓，Top-N，技术因子）。示例源码：`docs/examples/strategy_v2_cn_momentum_weekly.py`（csi500 需复制并改 `initialize` 内 pool/benchmark）。
2. 简短操作说明：邮件 SMTP 配置、回测步骤、signal 部署步骤 → **[A 股因子信号操作说明](../../trading/ASHARE_FACTOR_SIGNAL_CN.md)**。
3. 仅在「跑通必需」时对平台做最小改动（例如周调度或通知去重若有缺口）。
4. 本文档作为实现依据。

## 10. 风险与已知平台限制

- 公开股票池为快照起积累的 PIT，非完整官方历史成分。
- CN 基本面长历史不同步；第一阶段不依赖基本面。
- A 股无原生券商适配；本设计以 signal + 邮件为终点。
- 日线因子 + 周调仓需严格避免用到调仓时尚不可得的未来 bar。

## 11. 决议摘要

采用 **方案 2**：在现有 QuantDinger 上，用技术因子研究筛选 → Strategy V2 周频 Top-N 做多策略 → 回测 → `signal` + 邮件；双池对比；基本面与实盘留待后续阶段。
